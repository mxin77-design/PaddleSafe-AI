# PaddleSafe-AI

桨板安全与合规助手，一个面向桨板爱好者和活动组织者的安全评估网站原型。项目尝试把下水前的风险判断拆解为可理解的条件、规则和建议，并为后续接入天气、场地信息、AI 知识问答和数据库预留扩展方向。

> 当前版本是前端演示原型。风险分数由浏览器中的示例规则计算，不接入实时天气、官方场地数据库或大语言模型，不能作为实际下水决策依据。请以当地管理规定、场地公告和现场情况为准。

## 项目背景

桨板运动的参与人群持续扩大，但不同城市可合法开展活动的场地、管理要求和救援条件并不一致。初学者可能会因为附近有湖泊或河道，就把“离得近”当作“适合下水”，却不一定了解风力、水温、能见度、水域特点、装备和同行安排带来的风险。

目前，相关信息可能分散在场地公告、安全倡议、天气服务和俱乐部通知中。PaddleSafe-AI 以“下水前的安全判断”为切入点，探索如何把这些因素组织成清晰、可解释的提示。

## 项目目的

- 帮助用户在出行前梳理影响桨板活动安全的关键条件。
- 用可解释的规则评估展示风险因素，避免只给出没有依据的结论。
- 以安全和合规信息为产品核心，避免引导用户寻找未经确认的野水点。
- 为后续接入经过核验的场地信息、天气服务、AI 问答和组织者工具打下产品与技术基础。

## 当前功能

- 根据风力、水温、经验水平、是否单人、救生衣、夜间情况和水域类型进行演示性评分。
- 根据示例阈值输出“建议下水”“谨慎下水”或“不建议下水”，并展示触发原因。
- 提供城市、水域类型、经验和装备等输入项，调整条件后即时更新结果。
- 使用浏览器 `localStorage` 保存最近的评估结果数据，作为后续历史记录功能的原型基础。
- 提供用户端、组织者端、数据端的产品构想，以及上线步骤和数据库实体草图。
- 使用响应式布局，适配桌面和移动屏幕。

## 实施技术

当前版本采用无需构建步骤的静态网页技术：

- **HTML**：页面结构与表单控件。
- **CSS**：响应式布局、深色水域视觉、渐变与动效。
- **原生 JavaScript**：前端风险规则、结果展示和本地存储。
- **浏览器 `localStorage`**：本地保存演示数据；清除浏览器站点数据后记录会消失。

当前原型没有连接后端、数据库、实时天气 API 或大语言模型。评分逻辑只用于展示交互流程，正式使用前需要结合可靠数据来源进行规则设计、验证与更新。

## 本地运行

可以直接用浏览器打开 `index.html`。也可以在项目根目录启动一个静态文件服务器：

```bash
python3 -m http.server 4173
```

然后打开 <http://localhost:4173>。

## 展现成果

网站围绕一次下水前评估形成了可交互的演示流程：用户填写场景与个人条件，页面即时计算示例风险分，显示对应建议和风险原因。首页同时呈现规则引擎、AI 解释层与知识库的产品设想，并展示用户端、组织者端、上线阶段和数据库草图。

目前的演示重点是产品流程和交互表达。它尚未提供经核验的水域许可判断、实时天气预报或 AI 生成内容，也没有俱乐部后台、账号系统和云端历史记录。

## 后续上线与数据扩展

建议按阶段扩展，避免在原型阶段依赖尚未核验的数据：

1. **验证规则**：整理官方规范、场地管理要求和安全资料，为每条规则记录来源、适用区域、更新时间和维护者。
2. **接入服务端**：将评分逻辑迁移到后端 API；前端只负责收集输入并展示带有规则依据的结果。
3. **接入数据库**：可使用 PostgreSQL（例如 Supabase 或 Neon），逐步建立 `users`、`water_sites`、`assessments`、`safety_sources` 和 `incident_reports` 等数据表。
4. **接入 AI 能力**：先通过检索增强生成（RAG）回答基于资料的问题，并附上可追溯来源；风险拦截和硬性规则仍由经过验证的确定性逻辑处理。
5. **部署上线**：静态原型可部署到 GitHub Pages；加入服务端和数据库后，再部署 API，并通过环境变量管理密钥，避免将密钥写入前端代码。

## 适用范围

本项目是作品集和产品验证原型。示例分数、阈值和建议未经专业机构验证，不能替代当地主管部门、场地管理方、专业教练或救援人员的判断。只有在接入准确、及时且经过维护的数据，并完成充分验证后，才适合提供真实场景的辅助信息。
